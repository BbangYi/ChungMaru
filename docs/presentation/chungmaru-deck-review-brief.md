# Chungmaru Deck Review Brief

이 문서는 청마루 최종 발표 deck을 외부 GPT/리뷰어에게 검토시키기 위한 기준 자료다.

목표는 새 deck을 처음부터 다시 만드는 것이 아니라, 현재 24장 구성이 논리적으로 자연스러운지, 중복/누락/문구/디자인 문제가 있는지 찾는 것이다.

## 검토 요청 프롬프트

```text
너는 발표자료 구조/디자인/논리 검토자다.

아래는 청마루 캡스톤 발표 deck의 현재 구성과 반드시 들어가야 하는 내용이다.
목표는 새 슬라이드를 마음대로 만드는 것이 아니라, 현재 24장 구성이 논리적으로 자연스러운지, 중복/누락/문구/디자인 문제가 있는지 찾는 것이다.

프로젝트:
청마루는 온라인 댓글을 수집하고, 정제하고, 모델이 P/T/H 점수와 evidence span을 반환한 뒤, Chrome/Android 화면에서 실제 위치에 맞게 마스킹하거나 보류하는 시스템이다.

핵심 메시지:
단순 단어 차단이 아니라 댓글 후보, 모델 근거, 화면 위치가 같은 대상일 때만 중재한다.

발표에서 반드시 보여야 하는 축:

1. 문제 정의
- 단어 필터만으로는 오탐, 미탐, 오위치 마스크 문제가 생긴다.
- 모델 성능만이 아니라 수집/정제/화면 반영까지 맞아야 한다.

2. 시스템 구조
- Chrome Extension
- Android Accessibility/OCR 후보 수집
- Backend API
- KoHateMask v3 모델
- evidence span / bounds 기반 화면 반영

3. 모델 v3 내용
- KoHateMask v3
- KoNorm-v3 정규화
- mDeBERTa-v3-base
- P/T/H: Profanity, Toxicity, Hate
- label-mask BCE
- 내부 테스트 36,358개
- P/T/H macro F1 = 0.766, 95% CI [0.760, 0.773]
- External T+H F1 = 0.640
- Code-switch stress F1 = 0.855
- XLM-R + CRF span F1 = 0.554
- v2 topic-bias FP 72건이 v3 hard negative로 0건까지 줄었다는 근거
- 단, 정책 케이스와 모델 오류는 분리해서 설명해야 한다.

4. 파서/정제 내용
- raw text에서 UI 문구, 좋아요, 답글, 시간, 설정, 중복 후보 제거
- cleaned JSONL이 모델 입력으로 들어감
- 플랫폼별 수집 실패 지점: YouTube, Instagram, TikTok, Chrome 등
- 댓글이 아닌 텍스트가 모델 입력으로 섞이면 모델 문제가 아니라 입력 품질 문제가 된다.

5. 화면 반영 내용
- Chrome은 DOM span과 현재 텍스트 일치 여부로 구간 마스킹
- Android는 boundsInScreen, accessibility 후보, OCR ROI를 사용
- 실제 bounds가 없거나 stale 가능성이 있으면 마스킹 보류
- Android OCR/overlay는 아직 Validation Needed로 표현해야 한다.
- 완성 기능처럼 과장하면 안 된다.

6. 데모/완성도 내용
- 댓글 수집 → 정제 → 정규화 → 모델 판단 → evidence span → 화면 결과
- 정상 댓글, 욕설, 혐오, 우회 표현 사례가 있어야 한다.
- 보여줄 기능과 보류할 기능을 분리해야 한다.

현재 24장 구성:

1. 표지
- 현재 문제: 다른 장보다 dark tone이 강하고, 오른쪽 판단 경로 패널이 표지치고 과밀하다.
- 검토 필요: 표지는 프로젝트 정체성만 남기는 게 나은지.

2. 서비스 정의
- 댓글 후보에서 화면 중재까지의 서비스 정의.
- 검토 필요: 4단계 설명이 자연스러운지, 제목과 카드 개수가 맞는지.

3. 문제 정의
- 오탐, 미탐, 오위치가 함께 발생한다는 문제 제기.
- 검토 필요: 왜 이 문제가 중요한지 한 장에서 바로 이해되는지.

4. 시스템 구조
- 분석 결과를 화면 좌표로 검증하는 전체 구조.
- 검토 필요: Chrome/Android/Backend/Evaluation 관계가 명확한지.

5. 개발 계획과 현재 위치
- 4차 계획 중 검증 정리 단계.
- 검토 필요: 일정표인지 현재 상태표인지 목적이 모호하지 않은지.

6. 모델 평가 요약
- KoHateMask v3 수치 요약.
- 검토 필요: 수치가 너무 갑자기 나오지 않는지, v3 개선 의미가 보이는지.

7. 진행상황과 남은 검증
- 끝난 것과 남은 검증.
- 검토 필요: 발표자가 "현재 어디까지 됐는가"를 말하기 쉬운지.

8. 서버 API 계약
- P/T/H 점수와 evidence span을 같이 반환.
- 검토 필요: API 계약이 실제 화면 반영과 연결되는지.

9. 브라우저 구간 마스킹
- DOM span, 현재 텍스트, stale response guard.
- 검토 필요: Chrome의 핵심 차별점이 보이는지.

10. 브라우저 보호면
- site warning, search protection, wellbeing widget.
- 검토 필요: 댓글 마스킹 흐름에서 갑자기 확장 기능이 넓어지는 느낌이 없는지.

11. Android 좌표 근거
- 실제 bounds만 화면 마스킹 근거로 사용.
- 검토 필요: estimated range와 실제 bounds 차이가 잘 보이는지.

12. 파서 원본-정제 비교
- raw → cleaned 비교.
- 검토 필요: 원본에서 무엇이 제거됐는지 명확한지.

13. FP/FN 균형
- v3 학습 방식과 개선 포인트.
- 검토 필요: FP/FN 제목인데 내용이 v3 학습 구조 중심이라 어긋나지 않는지.

14. 실패 유형과 주제어 오탐
- 모델 오류와 정책 결정을 분리.
- 검토 필요: "정책 케이스"가 무슨 의미인지 관객이 바로 이해할 수 있는지.

15. 점수 구간 한계
- threshold만으로 분리되지 않는 사례.
- 검토 필요: 왜 운영 정책이 필요한지 결론까지 이어지는지.

16. 마스킹 처리 기록
- original → normalized → P/T/H score → evidence span → result.
- 검토 필요: 표가 읽기 쉬운지, 실제 예시처럼 보이는지.

17. Parser 오염 차단 기준
- 댓글 외 텍스트 제거.
- 검토 필요: 12번과 중복되는지, 아니면 규칙 설명으로 독립 가치가 있는지.

18. 플랫폼별 수집 문제
- 플랫폼별 extractor 문제.
- 검토 필요: 문제 나열이 아니라 해결 방향까지 보이는지.

19. 통합 데모 흐름
- 댓글 한 건이 화면 결과로 바뀌는 순서.
- 검토 필요: 완성도 근거로 가장 중요한 장인데 충분히 구체적인지.

20. 보고서 근거 매트릭스
- 모델/파서/통합 흐름을 보고서 근거로 정리.
- 검토 필요: 발표 슬라이드로 필요한 장인지, 부록/관리 장처럼 보이지 않는지.

21. 데모 범위와 보류 기준
- 보여줄 기능과 보류할 기능.
- 검토 필요: 솔직한 제약 설명인지, 미완성처럼 보이는지.

22. 남은 제약과 검증 항목
- 남은 위험과 검증 항목.
- 검토 필요: 21번과 중복되는지.

23. Android 오위치와 지연 진단
- 좌측: 오위치 발생 경로
- 우측: node/render/backend latency breakdown
- 검토 필요: 의도적으로 좌우 원인/측정 구조인데, 상하로 분리된 어색한 장처럼 보이지 않는지.

24. 최종 정리
- 지금 시연 범위, 검증 뒤 완료 표기, 보고서에 넣을 근거.
- 검토 필요: 발표 마지막 장으로 결론이 강한지.

검토 기준:
- 각 장이 "한 장당 주장 1개"를 지키는가?
- 표지부터 마지막 장까지 서사가 자연스럽게 이어지는가?
- 모델 v3 내용이 무분별하게 들어간 것이 아니라 필요한 장에만 들어갔는가?
- 같은 내용을 반복하는 장이 있는가?
- 빠진 핵심 근거가 있는가?
- 문구가 발표 슬라이드답게 짧고 자연스러운가?
- "~합니다", "~됩니다", "근거가 된다" 같은 문장체/AI식 문구가 남아 있는가?
- 표/카드/차트가 실제 정보를 전달하는가, 아니면 빈 장식처럼 보이는가?
- Android OCR/overlay를 완성 기능처럼 과장하지 않는가?
- 심사 기준의 기술성/완성도와 직접 연결되는가?

우선적으로 볼 지점:
- 20, 21, 22번이 서로 중복되는지
- 13번 제목과 내용이 맞는지
- 10번 브라우저 보호면이 전체 흐름에서 튀는지
- 1번 표지를 밝은 톤으로 바꾸는 것이 나은지

출력 형식:
1. 전체 서사 문제
2. 빠진 내용
3. 중복되거나 합칠 수 있는 슬라이드
4. 순서를 바꾸면 좋은 슬라이드
5. 슬라이드별 문제점
6. 표지 개선 방향
7. 문구 개선 예시
8. 최종 24장 재구성안
```
